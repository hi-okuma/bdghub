BODOGE-128 - 【セキュリティ】参加している部屋以外の情報を取得できないようにする To Do

  • 目的

    • MVPでは、　ユーザは参加している部屋の内部でのみ管理されるが、以下のセキュリティ要件・UX要件を満たす必要がある

      • 参加していない部屋の情報はアクセス不可
        → 不正なアクセスや改ざんを防止

      • リロードやアプリ切り替え時でも部屋やゲームの状態を維持

  • 採用方式

    • Firebase匿名認証

  • アーキテクチャ

    • ★部屋参加用のURLからアクセスしてきた場合はどうする？

      • 以前のuidやroom_idがローカルに残っていても、それらは新しい部屋には不要な情報となるため、削除して再度匿名認証を行う？

      • 現在の設計では、ユーザーはその部屋の中でのみ存在するものとしているが、
        今後、ユーザーを部屋の外で管理するような設計変更があった際には、この部分の修正が必要。

  • 課題

    • 利用されていない匿名ユーザのクリーンアップ

      • アップグレードすると、30 日以上経過した匿名アカウントを自動で削除するオプションを使用できる

      • 自前でスクリプトを用意すれば良さそう

      • しかし、ユーザのメタデータには、最後にサインインした日時程度しか記録されていない

      • 一旦、roomドキュメントを削除するタイミングでuidも削除する方針

  • 参考

    • Firebase Auth

      • スタートガイド

        • 認証の永続性

          • アプリの再起動やページの再読み込み後もユーザーの認証状態を維持する機能がデフォルトでサポートされている。ウェブ プラットフォームの場合、ユーザーの認証状態は IndexedDB に保存される。

          • デフォルトは ”firebase.auth.Auth.Persistence.LOCAL”

            • ブラウザ ウィンドウを閉じたり React Native でアクティビティが破棄されたりした場合でも、状態が維持されることを示します。この状態をクリアするには、明示的なログアウトが必要です。Firebase Auth のウェブ セッションは単一のホストを生成元とするため、単一のドメインでのみ永続化されることに注意してください。

          • ★デフォルトのままで問題ない？

      • 使用制限
